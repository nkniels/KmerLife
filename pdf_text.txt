Part 1. Mission and rules of engagement 
Mission 
You are the bootstrap agent for KmerLife, a real-time multiplayer browser life-simulation game set in 
Cameroon. Your job has five parts: 
1. Create the repository on the user's computer exactly as specified in Part 8. 
2. Prove it works (lint, typecheck, tests, simulator) before anything leaves the machine. 
3. Create the GitHub repository and push the first commit. 
4. Seed GitHub with labels, milestones, 26 issues and branch protection using the script already in 
the repository. 
5. Verify everything with the checklist in Part 9 and give the user a short report. 
 
Hard rules 
• Follow this document literally. Do not rename, reorder, "improve" or add files. Do not change 
any value in src/game/constants.ts or any test expectation to make a check pass. 
• Never ask for, accept, print or store a password or token. The user authenticates by running 
gh auth login themselves. 
• Never commit secrets. Only .env.example (empty values) may be committed. 
• No destructive git actions. No force-push, no deleting remote branches, no changing repository 
visibility without the user's explicit yes. 
• Do not scaffold Next.js, Supabase or any other tool. That is issue 1 and 2 for DEV-04. Do not 
add dependencies beyond those in package.json. 
• Ask only the questions in Part 2, once, in a single message. 
• If a step fails twice, stop. Report the exact command, the exact error, and what you tried. Do not 
work around it silently. 
• Work cross-platform. The user may be on Windows. Use git, node, npm and gh commands only; 
avoid shell-specific syntax such as && chaining. 
• Report honestly. If something could not be done (for example branch protection on a free private 
repository), say so plainly.

Part 4. Game design 
This part is the readable form of docs/GAME_DESIGN.md. The exact Markdown is in Part 8. 
1. Vision 
KmerLife is a browser life-simulation game set in Cameroon. Players create a character, earn FCFA, pay 
rent, join njangi groups and live in a shared Yaoundé (Douala and Buea come later). It is built for mobile 
phones, slow networks and short sessions, in French and English. 
Design pillars 
• Authentically Cameroonian. Njangi, radio trottoir, Eneo power cuts, benskin rides, concours. Not 
a reskin of another country's game. 
• Time is the currency of play. Energy and rent run on real clocks, so a few minutes a day is 
enough. 
• The server decides everything. Clients never edit money, energy or housing. 
• The city is never empty. Echoes (replayed real-player sessions) keep venues alive. 
• Fair and bounded. Seasons reset the economy, FCFA has no cash value, nothing can be bought 
for an advantage. 
 
2. Core loop 
1. Create a character: name, origin, city. 
2. Take a job. 
3. Work: spend energy, earn FCFA. 
4. Eat: spend FCFA, regain energy. 
5. Pay rent every week. Fall behind and arrears build up; fall far behind and you are evicted. 
6. Grow: move to better housing, join a njangi, travel, socialize. 
7. React to the world: rumors, power cuts, market swings. 
8. At season end the economy resets and the hall of fame is recorded. 
 
3. MVP scope

Venues 8 More per city

Out of scope: cash-out of FCFA, real-money purchases, NPC characters, voice chat, user-generated 
content.

8. Venues (MVP, Yaoundé) 
Mokolo Market, Central Market, Mfoundi Market, Bastos, Mvog-Mbi, Mvan Bus Station, Municipal Lake, 
Ngoa-Ekellé Campus. The data lives in content/venues.yaounde.json; names are message keys. 
9. Travel 
Each trip costs time and FCFA depending on mode (on foot, benskin, taxi, car) and distance. The 
numbers are set in constants when the travel module is built in week 3. 
10. Social 
• Presence per venue and chat per city, in real time. 
• Report and mute are mandatory from the first release; chat is rate-limited. 
• Echoes: anonymized recordings of real players' action sequences are replayed as dimmed, clearly 
labelled figures in quiet venues. They never affect real players' economy. 
 
11. Njangi (rotating savings) 
A njangi (tontine in French) is a group where everyone pays a fixed amount each round and one 
member takes the whole pot, in turn. 
• Group size 3 to 12 players; fixed contribution and round length set at creation. 
• The order of receiving is drawn at random when the group starts. 
• Each round the server collects every contribution; the pot is paid to that round's beneficiary only 
when all contributions are in. 
• A missed contribution gets a 24-hour grace period. After that the defaulter is removed, loses any 
claim to a future pot, and carries a visible "unreliable" mark for the season. 
• A member who already took the pot and then defaults owes the shortfall as debt. 
• Open questions for DEV-05 and DEV-01: group discovery, invitations, whether members may 
swap turns. 
 
12. World events and radio trottoir 
Event types: rumor, power_cut (Eneo outage), market_fluctuation, rent_due. 
• Rumors are short texts that spread through the city. Each has a hidden truth flag. If true, it has an 
economic effect (for example, prices in a market rise for 24 hours). Acting on a false rumor costs 
the player. 
• Power cuts stop work shifts in the affected city for a time. 
• Event text is written in advance (generated offline, reviewed by a human), stored in content/, in 
French and English. There is no live text generation at runtime. 
 
Content rules: no real people, real brands, politics, ethnic stereotypes, or references to the Anglophone 
crisis. 
13. Seasons 
• A season lasts about 90 days. 
• At the end: balances, housing and jobs reset; a hall of fame (wealthiest, most reliable njangi 
member) is kept. 
• Calendar-linked events: Youth Day (11 February), National Day (20 May), and the December trip 
to the village (descente au village), when players save for gifts.

14. Money, ads and legal 
• FCFA is virtual: it cannot be bought, sold or cashed out. No randomized paid rewards. 
• Phygital ads: local businesses can sponsor venues or billboards. Spending in the game can 
unlock real discount codes at the real business. Sponsors see redemption counts only. Sponsored 
content is clearly labelled. 
• Privacy: collect the minimum. Email for login. Phone numbers only for opt-in reminders. Publish a 
privacy notice in French and English, and have the current Cameroonian data-protection and 
cybersecurity rules checked before launch. 
• Decide a minimum player age before the pilot. 
 
15. Languages 
French and English are equal. Routes are prefixed /fr and /en. All text lives in src/messages/en.json 
and fr.json; content files store message keys only. 
16. Success metrics 
• Day-1 and day-7 retention of the pilot cohort. 
• Sessions per player per day and actions per session. 
• Median wealth against the targets in docs/ECONOMY.md. 
• Share of players evicted in their first two weeks. 
• Chat reports per 1 000 messages.

Part 5. Architecture and economy 
Readable forms of docs/ARCHITECTURE.md and docs/ECONOMY.md. The exact Markdown is in Part 8. 
Architecture 
1. Principles 
1. Pure rules kernel. All game rules live in src/game/ as pure functions: applyAction(state, 
action, now) returns a new state and events. No I/O, no clock, no randomness. 
2. Server-authoritative. Only the server writes player state. Clients may predict, but the server's 
answer wins. 
3. Lazy time. Energy regeneration and rent are computed from timestamps when a player acts or 
loads. No tick loop is needed for them. 
4. Idempotent actions. Every action carries a client-generated UUID key. Repeating a key never 
repeats the effect. 
5. Slow multiplayer. Real-time is limited to presence, chat and events. Everything else refreshes on 
a slow cadence. 
6. Vertical features. Each developer owns a feature end to end (rules, UI, content). The shared 
kernel stays small and is owned by the lead. 
7. Cheap by design. Free tiers, small bundles, cost alerts. Built for 3G and low-end Android. 
 
2. Layers 
Browser (Next.js, Zustand, local prediction with src/game) 
   |  POST /api/game  { action }              ^  realtime: presence, chat, events 
   v                                          | 
Server  src/server/handle-action.ts  --  applyAction (src/game)  --  Postgres (Supabase) 
 
3. One action, step by step 
1. The client creates a UUID key and POSTs the action. 
2. The server authenticates the player. 
3. It opens a transaction and selects the player row FOR UPDATE. 
4. If action_log already holds (player, key), it returns the stored result and stops. 
5. It calls applyAction(state, action, Date.now()), using the server clock only. 
6. On success it updates the player row (checking version), inserts action_log with the result, and 
inserts transactions rows for FCFA changes. 
7. It commits and returns the new state and events. 
8. If relevant, it publishes a realtime event. 
 
4. Data model (outline) 
All money columns are bigint FCFA. The kernel uses epoch milliseconds; the database uses 
timestamptz; a mapper in src/server/ converts. 
Table Key columns 
characters id, user_id (unique), name, origin, city, fcfa, energy

4. Targets (proposals for DEV-01 to confirm) 
1. A player who works every day is never evicted. 
2. A grinder earns at most about 3 times a casual player's weekly net. 
3. Median wealth grows roughly linearly over a season, not exponentially. 
4. A player can afford the studio deposit within about 4 weeks of steady play, but not in week 1. 
 
5. How to tune 
1. Change values in src/game/constants.ts only. 
2. Run npm run simulate with several seeds. 
3. Paste the output table into the pull request and into section 3 above. 
4. Do not merge economy changes without that evidence. 
 
6. Known simplifications 
• Energy regeneration over a period uses the housing tier at the start of the period. 
• Deposits are not refunded. 
• Eating is close to break-even against wages by design: it buys time, not profit. 
• The simulator's bots are simple; real players will be cleverer. 
 
Honest status of the economy 
The numbers are placeholders. The first simulation shows the faucet is larger than the sinks, so players 
hoard money. Issues 8 and 9 (simulator v2 and money sinks) exist to fix this before the pilot. Do not tune 
the numbers during bootstrap.

## Shared kernel (DEV-01), `src/game/` 
```ts 
applyAction(state: PlayerState, action: unknown, now: number): ActionResult

actionSchema, createPlayerSchema            // zod 
CITIES, MVP_CITIES, ORIGINS, JOB_IDS, JOBS, HOUSING_TIERS, MEAL, ...   // constants 
type PlayerState, GameAction, GameEvent, ActionResult, ErrorCode 
``` 
A feature module adds its actions by extending `actionSchema` and the engine switch in a PR 
reviewed by DEV-01. 
 
## Action API (DEV-01 and DEV-04), `src/server/` 
``` 
POST /api/game 
body:     GameAction              (includes the idempotency key) 
success:  { ok: true,  state: PlayerState, events: GameEvent[] } 
failure:  { ok: false, code: ErrorCode } 
``` 
Repeating the same key returns the stored result unchanged.

- Tables: `characters`, `action_log`, `transactions`, `world_state` (see `docs/ARCHITECTURE.md`). 
- Generated types: `src/lib/database.types.ts`. 
- Auth: the server resolves the current player from the session; clients never send a player id.

# KmerLife: Game Design 
 
## 1. Vision 
KmerLife is a browser life-simulation game set in Cameroon. Players create a character, earn FCFA, 
pay rent, join njangi groups and live in a shared Yaoundé (Douala and Buea come later). It is built 
for mobile phones, slow networks and short sessions, in French and English. 
 
### Design pillars 
- **Authentically Cameroonian.** Njangi, radio trottoir, Eneo power cuts, benskin rides, concours. 
Not a reskin of another country's game. 
- **Time is the currency of play.** Energy and rent run on real clocks, so a few minutes a day is 
enough. 
- **The server decides everything.** Clients never edit money, energy or housing. 
- **The city is never empty.** Echoes (replayed real-player sessions) keep venues alive. 
- **Fair and bounded.** Seasons reset the economy, FCFA has no cash value, nothing can be bought 
for an advantage. 
 
## 2. Core loop 
1. Create a character: name, origin, city. 
2. Take a job. 
3. Work: spend energy, earn FCFA. 
4. Eat: spend FCFA, regain energy. 
5. Pay rent every week. Fall behind and arrears build up; fall far behind and you are evicted. 
6. Grow: move to better housing, join a njangi, travel, socialize. 
7. React to the world: rumors, power cuts, market swings. 
8. At season end the economy resets and the hall of fame is recorded. 
 
## 3. MVP scope 
| Feature | MVP | Later | 
|---------|-----|-------| 
| City | Yaoundé | Douala, Buea | 
| Careers | 5 | More careers with levels and requirements (concours, dossiers) | 
| Venues | 8 | More per city | 
| Housing | 3 tiers | More tiers, furniture | 
| Transport | On foot, benskin, taxi, car | Clando, intercity bus | 
| Social | Venue presence, city chat | Friends, guilds | 
| Njangi | Week 5 | Variants | 
| Events | Rumors, power cuts | Water cuts, rainy season, scams | 
| Echoes | Week 5 | Richer replay | 
| Languages | French and English | Camfranglais flavor in event text | 
 
Out of scope: cash-out of FCFA, real-money purchases, NPC characters, voice chat, user-generated 
content. 
 
## 4. Characters 
- Name: 2 to 24 characters. 
- Origin: **privileged** (starts with 300 000 FCFA and a rented room) or **struggling** (starts 
with 0 FCFA, staying with relatives). 
- City: Yaoundé only in the MVP.

## 11. Njangi (rotating savings) 
A njangi (tontine in French) is a group where everyone pays a fixed amount each round and one 
member takes the whole pot, in turn. 
- Group size 3 to 12 players; fixed contribution and round length set at creation. 
- The order of receiving is drawn at random when the group starts. 
- Each round the server collects every contribution; the pot is paid to that round's beneficiary 
only when all contributions are in. 
- A missed contribution gets a 24-hour grace period. After that the defaulter is removed, loses any 
claim to a future pot, and carries a visible "unreliable" mark for the season. 
- A member who already took the pot and then defaults owes the shortfall as debt. 
- Open questions for DEV-05 and DEV-01: group discovery, invitations, whether members may swap 
turns.

- Rumors are short texts that spread through the city. Each has a hidden truth flag. If true, it 
has an economic effect (for example, prices in a market rise for 24 hours). Acting on a false rumor 
costs the player. 
- Power cuts stop work shifts in the affected city for a time. 
- Event text is written in advance (generated offline, reviewed by a human), stored in `content/`, 
in French and English. There is no live text generation at runtime. 
 
Content rules: no real people, real brands, politics, ethnic stereotypes, or references to the 
Anglophone crisis. 
 
## 13. Seasons 
- A season lasts about 90 days. 
- At the end: balances, housing and jobs reset; a hall of fame (wealthiest, most reliable njangi 
member) is kept. 
- Calendar-linked events: Youth Day (11 February), National Day (20 May), and the December trip to 
the village (descente au village), when players save for gifts. 
 
## 14. Money, ads and legal 
- FCFA is virtual: it cannot be bought, sold or cashed out. No randomized paid rewards. 
- **Phygital ads:** local businesses can sponsor venues or billboards. Spending in the game can 
unlock real discount codes at the real business. Sponsors see redemption counts only. Sponsored 
content is clearly labelled.

# KmerLife: Architecture 
 
## 1. Principles 
1. **Pure rules kernel.** All game rules live in `src/game/` as pure functions: `applyAction(state, 
action, now)` returns a new state and events. No I/O, no clock, no randomness. 
2. **Server-authoritative.** Only the server writes player state. Clients may predict, but the 
server's answer wins. 
3. **Lazy time.** Energy regeneration and rent are computed from timestamps when a player acts or 
loads. No tick loop is needed for them. 
4. **Idempotent actions.** Every action carries a client-generated UUID key. Repeating a key never 
repeats the effect. 
5. **Slow multiplayer.** Real-time is limited to presence, chat and events. Everything else 
refreshes on a slow cadence. 
6. **Vertical features.** Each developer owns a feature end to end (rules, UI, content). The shared 
kernel stays small and is owned by the lead. 
7. **Cheap by design.** Free tiers, small bundles, cost alerts. Built for 3G and low-end Android. 
 
## 2. Layers 
``` 
Browser (Next.js, Zustand, local prediction with src/game) 
   |  POST /api/game  { action }              ^  realtime: presence, chat, events 
   v                                          | 
Server  src/server/handle-action.ts  --  applyAction (src/game)  --  Postgres (Supabase) 
``` 
 
## 3. One action, step by step 
1. The client creates a UUID `key` and POSTs the action. 
2. The server authenticates the player. 
3. It opens a transaction and selects the player row `FOR UPDATE`. 
4. If `action_log` already holds (player, key), it returns the stored result and stops. 
5. It calls `applyAction(state, action, Date.now())`, using the server clock only. 
6. On success it updates the player row (checking `version`), inserts `action_log` with the result, 
and inserts `transactions` rows for FCFA changes. 
7. It commits and returns the new state and events. 
8. If relevant, it publishes a realtime event. 
 
## 4. Data model (outline) 
All money columns are `bigint` FCFA. The kernel uses epoch milliseconds; the database uses 
`timestamptz`; a mapper in `src/server/` converts. 
 
| Table | Key columns | 
|-------|-------------| 
| characters | id, user_id (unique), name, origin, city, fcfa, energy numeric(5,2), job_id, 
housing_tier, rent_arrears_fcfa, next_rent_due_at, last_accrued_at, season_id, version, created_at 
| 
| action_log | id, player_id, key, action jsonb, result jsonb, created_at, UNIQUE (player_id, key) 
|

| transactions | id, player_id, delta_fcfa, reason, season_id, created_at | 
| world_state | city, key, value jsonb, updated_at | 
| njangi_groups, njangi_members, njangi_rounds | Added in week 5 | 
| echo_recordings | Added in week 5 | 
 
Row-level security on every table: a player reads only their own rows; nothing in the browser can

## 5. Realtime 
- Channels: `city:{city}`, `venue:{venueId}`, and a private `player:{id}`. 
- The browser gets a scoped token from `/api/ably-token`; the provider API key never leaves the

(paid). 
- **ADR-0004 Seasons.** The economy resets about every 90 days to control inflation and give late 
joiners a fair start.

1. A player who works every day is never evicted. 
2. A grinder earns at most about 3 times a casual player's weekly net. 
3. Median wealth grows roughly linearly over a season, not exponentially. 
4. A player can afford the studio deposit within about 4 weeks of steady play, but not in week 1.

1. Change values in `src/game/constants.ts` only. 
2. Run `npm run simulate` with several seeds. 
3. Paste the output table into the pull request and into section 3 above. 
4. Do not merge economy changes without that evidence.

- Energy regeneration over a period uses the housing tier at the start of the period. 
- Deposits are not refunded. 
- Eating is close to break-even against wages by design: it buys time, not profit. 
- The simulator's bots are simple; real players will be cleverer.

  MS_PER_MINUTE,

const round2 = (n: number): number => Math.round(n * 100) / 100; 
 
/** 
 * Lazy time accrual. Brings a player's state up to `now` by computing, from timestamps, 
 * what the simulation "would have done": energy regeneration and rent charges. 
 * Pure and idempotent: accrue(accrue(s, t), t) equals accrue(s, t). 
 * No background tick is needed for any of this. 
 */ 
export function accrue( 
  state: PlayerState, 
  now: number, 
): { state: PlayerState; events: GameEvent[] } { 
  if (now <= state.lastAccruedAt) return { state, events: [] }; 
 
  const events: GameEvent[] = []; 
  const next: PlayerState = { ...state }; 
  const housing = HOUSING_TIERS[state.housingTier]; 
 
  // Energy 
  const minutes = (now - state.lastAccruedAt) / MS_PER_MINUTE; 
  const regenPerMin = ENERGY_REGEN_PER_MIN * housing.regenMult; 
  next.energy = round2(Math.min(ENERGY_MAX, state.energy + minutes * regenPerMin)); 
 
  // Rent (auto-debit; any shortfall becomes arrears) 
  if (housing.rentFcfa > 0 && now >= state.nextRentDueAt) { 
    const periodsElapsed = Math.floor((now - state.nextRentDueAt) / RENT_INTERVAL_MS) + 1; 
    const periodsCharged = Math.min(periodsElapsed, MAX_RENT_CATCHUP); 
    const totalDue = periodsCharged * housing.rentFcfa; 
    const paid = Math.min(next.fcfa, totalDue); 
    const added = totalDue - paid; 
    next.fcfa -= paid;

    next.rentArrearsFcfa += added; 
    next.nextRentDueAt = state.nextRentDueAt + periodsElapsed * RENT_INTERVAL_MS; 
    events.push({

      periods: periodsCharged, 
      paidFcfa: paid,

const fail = (code: ErrorCode): ActionResult => ({ ok: false, code }); 
 
/** 
 * THE rules of the game as one pure function. 
 * Given the current state, an action and the current time, return the new state and events, 
 * or an error code. No I/O, no clock, no randomness, no mutation of the inputs. 
 * 
 * The server calls this inside a row lock and persists the result. 
 * The client may call it for optimistic prediction; the server's answer always wins. 
 */ 
export function applyAction(state: PlayerState, action: unknown, now: number): ActionResult { 
  const parsed = actionSchema.safeParse(action); 
  if (!parsed.success) return fail('INVALID_ACTION'); 
  const act = parsed.data; 
 
  const accrued = accrue(state, now); 
  const s: PlayerState = { ...accrued.state }; 
  const events: GameEvent[] = [...accrued.events]; 
 
  switch (act.type) { 
    case 'take_job': { 
      if (s.jobId === act.jobId) return fail('SAME_JOB'); 
      s.jobId = act.jobId; 
      events.push({ type: 'job_taken', jobId: act.jobId }); 
      break; 
    } 
    case 'work': { 
      if (s.jobId === null) return fail('NO_JOB'); 
      const job = JOBS[s.jobId]; 
      if (s.energy < job.energyCost) return fail('NOT_ENOUGH_ENERGY'); 
      s.energy = Math.round((s.energy - job.energyCost) * 100) / 100; 
      s.fcfa += job.wageFcfa; 
      events.push({ type: 'worked', earnedFcfa: job.wageFcfa, energySpent: job.energyCost }); 
      break; 
    } 
    case 'buy_meal': { 
      if (s.energy >= ENERGY_MAX) return fail('ENERGY_FULL'); 
      if (s.fcfa < MEAL.costFcfa) return fail('NOT_ENOUGH_FCFA'); 
      const gained = Math.min(MEAL.energy, ENERGY_MAX - s.energy); 
      s.fcfa -= MEAL.costFcfa; 
      s.energy = Math.round((s.energy + gained) * 100) / 100; 
      events.push({ type: 'meal_bought', costFcfa: MEAL.costFcfa, energyGained: gained }); 
      break; 
    } 
    case 'pay_arrears': { 
      if (s.rentArrearsFcfa === 0) return fail('NOTHING_OWED'); 
      const pay = Math.min(act.amountFcfa, s.rentArrearsFcfa); 
      if (s.fcfa < pay) return fail('NOT_ENOUGH_FCFA'); 
      s.fcfa -= pay; 
      s.rentArrearsFcfa -= pay; 
      events.push({ type: 'arrears_paid', paidFcfa: pay, remainingFcfa: s.rentArrearsFcfa }); 
      break; 
    } 
    case 'move_housing': { 
      if (act.tier === s.housingTier) return fail('SAME_HOUSING'); 
      if (s.rentArrearsFcfa > 0) return fail('HAS_ARREARS'); 
      const deposit = HOUSING_TIERS[act.tier].depositFcfa; 
      if (s.fcfa < deposit) return fail('NOT_ENOUGH_FCFA'); 
      s.fcfa -= deposit; 
      s.housingTier = act.tier; 
      s.nextRentDueAt = now + RENT_INTERVAL_MS; 
      events.push({ type: 'moved', tier: act.tier, depositFcfa: deposit }); 
      break; 
    } 
  } 
 
  s.version = state.version + 1; 
  return { ok: true, state: s, events }; 
}

function play(strategy: Strategy, rand: () => number, days: number, id: string): PlayerState { 
  const origin = rand() < 0.5 ? 'privileged' : 'struggling'; 
  let s = createPlayer({ id, name: `Bot ${id}`, origin, city: 'yaounde' }, START); 
  const job = JOB_IDS[Math.floor(rand() * JOB_IDS.length)] as JobId; 
  s = step(s, { type: 'take_job', key: nextKey(), jobId: job }, START); 
 
  for (let d = 0; d < days; d++) { 
    for (let l = 0; l < strategy.loginsPerDay; l++) { 
      const now = 
        START + d * MS_PER_DAY + Math.floor((l * 16 * MS_PER_HOUR) / strategy.loginsPerDay) + 7 * 
MS_PER_HOUR; 
 
      if (s.rentArrearsFcfa > 0) { 
        s = step(s, { type: 'pay_arrears', key: nextKey(), amountFcfa: Math.min(s.fcfa, 
s.rentArrearsFcfa) || 1 }, now); 
      } 
      // work until exhausted, eating when allowed 
      for (let guard = 0; guard < 40; guard++) { 
        const before = s; 
        s = step(s, { type: 'work', key: nextKey(), }, now); 
        if (s === before) { 
          if (s.energy < strategy.eatBelowEnergy || (strategy.eatBelowEnergy > 0 && guard === 0)) { 
            const afterEat = step(s, { type: 'buy_meal', key: nextKey() }, now); 
            if (afterEat === s) break; 
            s = afterEat; 
          } else break; 
        } 
      } 
      if (strategy.upgrades && s.rentArrearsFcfa === 0) { 
        const next = (s.housingTier + 1) as 1 | 2; 
        if (s.housingTier < 2) { 
          const need = HOUSING_TIERS[next].depositFcfa + 3 * HOUSING_TIERS[next].rentFcfa; 
          if (s.fcfa >= need) s = step(s, { type: 'move_housing', key: nextKey(), tier: next }, 
now); 
        } 
      } 
    } 
  } 
  // final accrual at the end of the horizon 
  const end = START + days * MS_PER_DAY; 
  const r = applyAction(s, { type: 'take_job', key: nextKey(), jobId: s.jobId ?? 'tailor' }, end); 
  return r.ok ? r.state : s; 
} 
 
function pct(sorted: number[], p: number): number { 
  if (sorted.length === 0) return 0; 
  const idx = Math.min(sorted.length - 1, Math.floor((p / 100) * sorted.length)); 
  return sorted[idx] as number; 
}

import { readFileSync } from 'node:fs'; 
import { describe, expect, it } from 'vitest'; 
import { ERROR_CODES, JOB_IDS } from '../../src/game'; 
 
const read = (p: string): unknown => JSON.parse(readFileSync(new URL(p, import.meta.url), 'utf8')); 
type Messages = { job: Record<string, string>; error: Record<string, string>; venue: Record<string, 
string> }; 
 
describe('content and messages stay in sync', () => { 
  const en = read('../../src/messages/en.json') as Messages; 
  const fr = read('../../src/messages/fr.json') as Messages; 
 
  it('en and fr have identical key sets', () => { 
    const keys = (o: unknown, prefix = ''): string[] => 
      Object.entries(o as Record<string, unknown>).flatMap(([k, v]) => 
        typeof v === 'object' && v !== null ? keys(v, `${prefix}${k}.`) : [`${prefix}${k}`], 
      ); 
    expect(keys(fr).sort()).toEqual(keys(en).sort()); 
  }); 
 
  it('every job has a label in both languages', () => { 
    for (const id of JOB_IDS) { 
      expect(en.job[id]).toBeTruthy(); 
      expect(fr.job[id]).toBeTruthy(); 
    } 
  }); 
 
  it('every error code has a message in both languages', () => { 
    for (const code of ERROR_CODES) { 
      expect(en.error[code]).toBeTruthy(); 
      expect(fr.error[code]).toBeTruthy(); 
    } 
  }); 
 
  it('every venue nameKey resolves in both languages', () => { 
    const venues = read('../../content/venues.yaounde.json') as { venues: { id: string; nameKey: 
string }[] }; 
    expect(venues.venues.length).toBe(8); 
    for (const v of venues.venues) { 
      const key = v.nameKey.replace('venue.', ''); 
      expect(en.venue[key], v.id).toBeTruthy(); 
      expect(fr.venue[key], v.id).toBeTruthy(); 
    } 
  }); 
});
